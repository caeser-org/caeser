# Caeser product demo recorder

Generates the landing-page product demo from a **real** Caeser investigation:
a real failed GitHub Actions check and the real PR comment the Caeser GitHub
App publishes. Nothing is mocked — the recorder only films GitHub.

```
demo/
├── record.sh              # capture + assemble in one command
├── capture.mjs            # Playwright, deterministic camera choreography
├── scripts/
│   ├── assemble.mjs       # FFmpeg: WebM, MP4, GIF, WebP poster
│   ├── inspect.mjs        # prints target geometry (retune the camera)
│   └── login.mjs          # optional session for private repos
└── out/                   # deliverables (git-ignored)
    ├── ceaser-demo.webm
    ├── ceaser-demo.mp4
    ├── ceaser-demo.gif
    └── ceaser-demo-poster.webp
```

## Deliverables

| File | Format | Notes |
| --- | --- | --- |
| `ceaser-demo.webm` | VP9, 60 fps, 1920×1080 | primary asset, < 3 MB |
| `ceaser-demo.mp4` | H.264 + faststart | browser-compatibility fallback |
| `ceaser-demo.gif` | animated GIF | optional sharing asset |
| `ceaser-demo-poster.webp` | WebP | static preview / poster frame |

## Requirements

- macOS or Linux with Google Chrome installed (Playwright drives the real Chrome
  channel — no bundled browser download).
- Node 20+, FFmpeg 6+.
- `cwebp` (from `webp`) for the poster; FFmpeg falls back to a PNG otherwise.

```sh
cd demo && npm install
```

## Regenerate from an existing PR

The recorder never runs CI. Point it at a pull request whose CI has already
failed and whose Caeser comment already exists:

```sh
./record.sh --pr https://github.com/caeser-org/ceaser-demo/pull/1
```

That single command captures the two shots and writes the four assets to `out/`.

### Private repositories

The default target is public, so no credentials are involved and the recording
never shows a session. For a private repository, create a reusable session once:

```sh
node scripts/login.mjs          # sign in once; saved to .auth/state.json
./record.sh --pr https://github.com/<org>/<repo>/pull/<n>
```

`.auth/` and `out/` are git-ignored. Credentials are never read by the script
or written into the recording.

### Tuning

```sh
node scripts/inspect.mjs <pr-url>     # document coordinates of the key elements
```

Update `SHOTS` in `capture.mjs` (`origin`, `scroll`, `zoom`, `timeline`) if
Caeser's comment layout changes. `capture.mjs` prints a framing report after
each shot so you can confirm the evidence is centred before assembling.

The renderer forces `scroll-behavior: auto` and scrolls the document directly,
so GitHub's `scroll-behavior: smooth` cannot make frames depend on animation
timing. The comment shot is framed so the App's avatar and the
`tree.go:418 node.getValue` lead are both in view.

```sh
node capture.mjs --pr <url> --fps 30   # constant frame rate
node scripts/assemble.mjs --crf-webm 34
```

## How the demo is produced

### 1. A genuine investigation

The demo targets [`caeser-org/ceaser-demo`](https://github.com/caeser-org/ceaser-demo),
an isolated reproduction built from the gin-gonic/gin routing tree at the
pre-fix revision used by evaluation case **`go-002-gin-skipped-nodes`**. PR #1
adds the upstream regression test, CI fails, and the Caeser workflow
(`caeser-org/caeser/.github/workflows/ci-diagnose.yml@main`) investigates the
real failure and publishes a real comment from the repository's own GitHub App
(`caeser-diagnosis[bot]`), so the bot's avatar appears in the comment.

The App is installed only on `caeser-demo` and is granted **Issues: read and
write** and **Pull requests: read and write** — GitHub requires the pull-request
permission to comment on a PR, and the reusable workflow must request both when
it mints the App token. Its logo must be a square image under GitHub's 1 MB
App-logo limit.

The published report localizes to `tree.go` `node.getValue` from observed stack
frames and ranks it against `gin.go` `handleHTTPRequest` / `ServeHTTP`, with
evidence IDs — exactly Caeser's current output, unmodified.

The reproduction command is `go test -run TestLateRouteRegistrationSkippedNodes .`,
matching the evaluation case so the failure is deterministic.

### 2. Deterministic capture

`capture.mjs` films two shots of that PR:

1. `/pull/<n>/checks` — the failed `test` run.
2. `/pull/<n>` — scrolling to the Caeser comment, then a camera zoom onto the
   `tree.go:418 node.getValue` lead (keeping the App avatar and the comment
   header framed).

Rather than relying on screencast timing, each output frame is generated by
computing the camera state (scroll + eased zoom) for that exact virtual
timestamp, applying it, and screenshotting. This yields a true constant frame
rate with perfectly smooth, reproducible motion.

- 1920×1080, 16:9, GitHub dark mode (`prefers-color-scheme: dark`).
- No cursor overlay, no notifications, no browser chrome, no loading states.
- Choreography: eased scroll and a single eased zoom per shot, ending on a hold
  of the evidence.

### 3. Assembly

`scripts/assemble.mjs` concatenates the two shots (hard cut) with FFmpeg and
emits the WebM, MP4, GIF and poster. Video-only: no music, narration, captions
or decorative effects.

## When Caeser's output changes

1. Update the demo PR: open a PR on `caeser-org/ceaser-demo` (or any new target)
   that triggers a real, deterministic CI failure.
2. Wait for the Caeser workflow to publish its comment.
3. `./record.sh --pr <pr-url>`
4. Review `out/`.

If the comment's structure changed enough to move the evidence, run
`node scripts/inspect.mjs <pr-url>` and nudge the `SHOTS` coordinates.
