# Caeser v0.1.2

This release wires the fresh independent batch into the evaluation workflow. The
diagnosis engine is unchanged from v0.1.1. No verification gate, promotion rule,
or abstention rule was modified.

## What changed

- `.github/workflows/final-eval.yml` now runs `fresh10-manifest.json` in addition
  to the earlier exposed holdout. It reports verified case count and exact
  function hits in the job summary, and uploads the fresh batch results.
- The ten-case fresh batch stays frozen and marked unexposed. It is a validation
  set, not a tuning target.

## Get started

Build from source with Go 1.26:

```sh
git clone https://github.com/caeser-org/ceaser.git
cd caeser
go build -o caeser ./cmd/caeser
./caeser version
./caeser init
./caeser evidence --ci-log failed.log > report.json
./caeser brief --report report.json
```

For continuous integration, use the reusable workflow documented in
`docs/ci-integration.md`, pinned to `v0.1.2`.
